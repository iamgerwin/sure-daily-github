## Summary
Fixes a silent test-loss bug in the conflict fixer: when both sides of a merge conflict added tests to the same test file, the newer-hunk-wins strategy kept only one side's tests — the suite still passed (it had fewer tests), so the test gate could not catch it. Test-file conflicts now use a union strategy that keeps every added test from both sides, with a modified-base safety escalation and a test-count guard. Also adds a `conflictFixer.sourceHunks` option (`push`|`claude`|`escalate`, default `push`) so the upcoming PR-maintenance automation can route source-hunk conflicts to an LLM resolver instead of pushing them blind.

## Before vs After
- Before: both-sides-added test conflict → newer side wins, older tests silently dropped; source hunks auto-pushed with no semantic check and no way to change that.
- After: test paths (`test/**`, `**/*.test.js`, `**/*.spec.js`, `__tests__/**`) resolve by union (base→ours→theirs, all added lines kept); if either side modified base lines inside a test conflict, the path escalates to manual review instead of auto-resolving; a test-count check rejects any resolution whose test count drops below either parent; source-hunk behavior is configurable with the current default preserved.

## Testing / Verification
- `npm test`: 235 tests, 235 pass, 0 fail (223 pre-existing + 12 new).
- New tests cover: union ordering with both-sides-added tests; modified-base escalation trigger; `sourceHunks` config validation (rejects bad values, defaults to `push`); test-count drop rejection before push.

## Regression Analysis
Default CLI behavior is unchanged (`sourceHunks` defaults to `push`); the only default-visible change is the union strategy on test files, which strictly widens what is kept. Escalation only triggers where the previous behavior was provably lossy (modified base lines in test hunks). The test-count guard runs on the resolved tree before any push and fails closed.

## Others
`config/config.example.yaml`, `docs/CONFLICT_FIXER.md`, and `CLAUDE.md` document the new option and the union strategy. None of the `escalate`/`claude` paths bypass the test gate, repo gate, or ledger.
